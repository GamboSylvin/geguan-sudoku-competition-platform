# Sudoku Arena MVP — Question 2 Decision Summary

## Q2 — Competition Creation, Setup & Lifecycle

### Q2.1 — Stage and Round Configuration

For the current MVP, the competition structure is **fixed**.

- Stages are predefined.
- Rounds are predefined.
- Stage/round order is predefined.
- Durations are predefined.
- Preparation periods are predefined.
- Competition rules are predefined.
- Admin does **not** configure stages, rounds, durations, or rules during competition creation.

A future configurable competition engine may be introduced later, but it is outside the current MVP.

---

### Q2.2 — Competition Creation Inputs

The admin provides:

- Competition name
- Competition description
- Category: U6–U20
- Participant Excel file
- Competition question PDF

The following are not required:

- Venue
- Organizer/admin name
- Manually entered creation date/time

The creation date/time is generated by the server/system.

The admin does not manually configure stages or rounds. Questions from the uploaded PDF are assigned to the predefined rounds.

---

### Q2.3 — Participant Excel Validation

The participant Excel file is validated before any participant data is committed.

Required participant information:

- Name
- Category
- Team

Validation rules:

- Missing name → reject the entire document.
- Invalid category → reject.
- Exact duplicate rows → may be automatically removed, keeping one copy.
- The same person appearing in conflicting teams → reject.
- Invalid team size → reject.
- No partial participant import is allowed after validation failure.

Errors should identify the problem clearly, for example:

> Missing name — row 17.

The system may clean exact duplicates but must never silently resolve contradictory participant information.

---

### Q2.4 — Participant Account Generation

After a valid participant Excel file is imported:

1. Participants are created.
2. Teams are created.
3. Player accounts are created.
4. Credentials are generated.
5. The admin can export the generated username/password list.

The organizer does not need to provide player credentials.

---

### Q2.5 — Re-uploading Participant Excel

Before publication, the admin may replace the participant Excel file.

The new file:

- Must go through full validation.
- Replaces the previous participant dataset only if valid.
- Does not affect the existing valid dataset if validation fails.

After publication:

- Participant Excel cannot be replaced.

---

### Q2.6 — Account Preservation During Replacement

When a corrected Excel file replaces the previous one:

- Participants whose relevant information is exactly unchanged keep their existing accounts/credentials.
- New participants receive new accounts/credentials.
- Participants whose information changes receive new credentials.
- Removed participants are removed from the active participant set.

The replacement is atomic.

The exact identity-matching rule for determining whether two participant records represent the same person remains an implementation detail to define later.

---

### Q2.7 — Changing Participant Information

A changed participant record is treated as a significant participation change rather than a simple in-place update.

Example:

> John — U14 — Team A  
> →  
> John — U14 — Team B

This results in:

- Removing the old participation record.
- Creating the new participation record.
- Generating new credentials.
- Creating a new competition participation identity.

---

### Q2.8 — Publish Readiness

The **Publish** action is available only when all required competition data is ready:

- Competition information exists.
- Participant Excel is valid.
- Participants and teams have been created.
- Player accounts and credentials exist.
- Question PDF exists.
- PDF import/extraction succeeded.
- Questions have been assigned to the appropriate predefined rounds.
- Fixed stages/rounds are valid.
- Exactly one judge has been assigned.

Publishing also generates the competition entry link/QR code.

After publication, the competition configuration becomes locked.

---

### Q2.9 — Question PDF Import

The MVP uses a **strict predefined PDF format**.

No OCR is included in the MVP.

If the PDF:

- Has the wrong structure,
- Cannot be parsed,
- Cannot be extracted,
- Or cannot be classified/assigned correctly,

then the entire import is rejected.

No partial question data is committed.

The admin receives an explanation of the failure and must either provide a valid PDF or use an existing question pack from the Question Bank.

---

### Question Pack / Question Bank

The competition's imported questions form a **competition-level question pack**.

After successful import:

- The question pack is saved for the competition.
- The pack can also be stored in the global Question Bank.
- Future competitions may reuse existing question packs.
- Future competitions may alternatively import a new PDF.

Question packs contain the actual questions/puzzles and follow the predefined structure/types.

If the admin selects the Question Bank when it is empty, the system informs them that no question packs are available.

---

### Q2.10 — Judge Assignment

Each competition has **exactly one assigned judge**.

The judge:

- Must belong to the organization.
- Must be assigned before publication.
- Can be selected from the organization's existing judge list.
- Or a new judge can be created during competition setup.

When creating a new judge:

- The admin enters the judge's name.
- The system creates the judge account.
- Credentials are generated.
- Credentials are shown immediately in a modal/popup.

A simple organization-level judge list is sufficient for the MVP.

---

### Q2.11 — Judge Reuse Across Competitions

A judge account can be reused across multiple competitions **over time**.

However:

> A judge can be assigned to only one ongoing competition at a time.

Example:

- Judge A → Competition 1: allowed.
- Competition 1 is still ongoing.
- Judge A → Competition 2: **not allowed**.
- Competition 1 finishes.
- Judge A becomes available again.

The system must therefore check whether the judge currently has an active competition assignment before allowing assignment.

---

### Q2.12 — When a Competition Becomes Finished

A competition becomes `FINISHED` in either of two ways.

#### Automatic finish

The final round of the final stage ends normally.

#### Manual finish

The judge clicks **Finish Competition** before the normal end.

In both cases:

- Competition status becomes `FINISHED`.
- The judge's assignment ends.
- The judge becomes available for another competition.
- The competition can no longer continue.

---

### Q2.13 — Manual Early Finish During an Active Round

If the judge clicks **Finish Competition** while a round is active:

1. Immediately end the current round.
2. Auto-submit every player's latest saved state.
3. Calculate scores.
4. Finish the competition.
5. Preserve the resulting final competition results.

This uses the normal:

`Save → Submit → Score → Finish`

flow.

---

### Q2.14 — Access After Competition Finish

After a competition is `FINISHED`:

#### Judge

The judge's operational responsibility ends.

The judge no longer has active operational access to the competition.

#### Admin

The admin retains access to the competition's results and data.

#### Player

Players do not receive final results through their own competition screen.

#### Big Screen

The big screen becomes read-only and can display the final competition state/results.

---

### Q2.15 — Post-Competition Results

For the MVP, the admin only needs simple final results:

- Final ranking
- Final scores

Detailed player-level analysis is **out of scope** for the MVP.

Not included:

- Individual submitted grids
- Per-question answers
- Submission timestamps
- Detailed scoring breakdown
- Detailed move/state history

These may be considered in a future version.

---

### Q2.16 — Competition Cancellation

Cancellation is an exceptional case, not a normal lifecycle action.

The competition can be canceled only when something has gone wrong with the competition and the judge has stopped it prematurely.

A canceled competition is considered **invalid**.

Therefore:

- The competition is marked `CANCELLED`.
- Final results are not released.
- Competition result data is not preserved.
- We do not bother completing the normal auto-submit/scoring process for cancellation.
- The admin can create a new competition to replace it.

Important distinction:

### Finished

Valid competition:

`RUNNING → FINISHED`

Results are preserved.

### Cancelled

Invalid competition:

`RUNNING → CANCELLED`

Results are discarded.

---

### Q2.17 — Pause Behavior

When the judge pauses the competition:

- The timer stops.
- Player interaction stops.
- Players cannot modify their grids.
- Players are notified that the competition is paused.
- The exact competition state is preserved.
- The judge can resume later.
- The same judge remains assigned to the competition.

Pause does not finish or cancel the competition.

---

### Q2.18 — Pause Is Global

There is **one global Pause Competition action**.

There is no separate round-level pause.

When the competition is paused:

- Everyone is paused.
- The current stage remains unchanged.
- The current round remains unchanged.
- Player states remain unchanged.
- The timer stops.
- The big screen reflects the paused state.
- No automatic transition can occur.
- Nothing in the competition progresses.

The pause is therefore a global competition state.

---

### Q2.19 — Paused UI

When the competition is paused:

#### Big Screen

Displays an explicit paused state, such as:

> **Competition Paused**

#### Player Screen

Displays a blocking notification/modal, such as:

> **Competition paused. Please wait for the judge to resume.**

Players cannot continue interacting with the puzzle while paused.

---

### Q2.20 — Resume Behavior

When the judge resumes a paused competition:

1. The competition remains frozen initially.
2. A short countdown is displayed:
   - 3
   - 2
   - 1
   - Start
3. After the countdown finishes, the competition resumes.
4. The timer starts again.
5. Players continue from exactly the state they had before the pause.

The resume countdown does **not** consume the round's remaining competition time.

Lifecycle:

`PAUSED → RESUME COUNTDOWN → RUNNING`

---

# Core Competition Lifecycle

The decisions above produce the following simplified lifecycle:

```text
                    ┌──────────────┐
                    │   PUBLISHED  │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │    RUNNING   │
                    └──────┬───────┘
                           │
             ┌─────────────┴─────────────┐
             │                           │
          PAUSE                        FINISH
             │                           │
             ▼                           ▼
        ┌──────────┐              ┌────────────┐
        │  PAUSED  │              │  FINISHED  │
        └────┬─────┘              └────────────┘
             │
          RESUME
             │
             ▼
        ┌──────────┐
        │  RUNNING │
        └──────────┘


        Exceptional invalid competition:

        RUNNING ──────────────► CANCELLED
                                  │
                                  ▼
                            Results discarded
```

# Q2 — Final MVP Principles

1. **Fixed competition structure** for the MVP.
2. **Strict participant validation** with atomic replacement/import.
3. **System-generated player accounts and credentials.**
4. **One judge per competition.**
5. **One ongoing competition per judge.**
6. **Competition automatically or manually finishes.**
7. **Manual finish during a round performs normal auto-submit and scoring.**
8. **Cancellation represents an invalid competition and discards its results.**
9. **Pause is global, not round-specific.**
10. **Pause freezes the entire competition and its timer.**
11. **Resume uses a short countdown before time continues.**
12. **Finished competitions are read-only for the big screen.**
13. **Admins retain access to final ranking and scores.**
14. **Detailed post-competition analytics are out of MVP scope.**
15. **Question PDFs use a strict predefined format; no OCR.**
16. **Question packs can be reused through the global Question Bank.**
17. **Publishing locks competition configuration.**
